# Vocello 2.2.2

Released **2026-07-25**. The second same-day packaging patch after
[2.2.1](v2.2.1.md), and the tag that carries the first iOS TestFlight build. One fix: the
iOS release-lane artifact verifier only read version identity from the app-target block of
`project.yml`, so 2.2.1's move of `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` to project
scope (itself required by App Store Connect) failed the tag-frozen `ipa-verification` step.
The verifier now resolves settings the way Xcode does — target scope first, then project
scope — with a regression test bound to the live project file. No app code changed; on
macOS, 2.2.2 is functionally identical to 2.2.0.

> **Upgrading?** Nothing to do beyond the usual drag-install if you want the version number
> to match. Installed models, history, and saved voices carry over automatically.

[Download v2.2.2](https://github.com/PowerBeef/Vocello/releases/tag/v2.2.2) · [All releases](https://github.com/PowerBeef/Vocello/releases)

## Requirements

Unchanged from [2.2.0](v2.2.0.md#requirements): macOS 26.0+, Apple Silicon, 8 GB RAM
minimum, ~7 GB free disk for the Speed variants, internet for one-time model downloads.

## What changed

- `scripts/verify_ios_release_artifacts.py` resolves `MARKETING_VERSION` and
  `CURRENT_PROJECT_VERSION` with Xcode-style inheritance (target block, then the
  project-level `settings:` block) instead of requiring them at target scope.
- A regression test binds `load_expected_identity()` to the real `project.yml`, so a
  settings-layout change fails the deterministic suite before a tag can freeze the
  mismatch.

## Install

1. Download [`Vocello-macos26.dmg`](https://github.com/PowerBeef/Vocello/releases/download/v2.2.2/Vocello-macos26.dmg).
2. Open the DMG and drag `Vocello.app` into `/Applications`.
3. Launch, open Settings, and download the model variants you want.
